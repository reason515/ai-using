开　场

开场

我们面对的现实

  • 模型与工具几乎「按月换代」，照搬旧教程容易失效
  • 真正稳定的是：底层逻辑 + 试错 + 复盘
本分享目标：给你一套可迁移的协作框架，而不是工具清单
Part 02

核心理念

核心理念

最佳实践会过期，底层逻辑不会

  • 模型进化太快 → 不要迷信「唯一正确流程」
  • 有效路径：优秀底层逻辑 + 不断尝试 + 总结反思
  • 持续探索模型/工具进化，并迭代自己的工作方式
  • 新概念、新工具层出不穷——结合自身选择性采用，不盲目跟风；自己的理解和实践最重要
核心理念

先规划，再交给 AI——把注意力留给高价值事项

任务的主体永远是人：是你告诉 AI 做什么，而不是去问 AI「我应该做什么」。人若没有清晰想法，产出质量通常不会太高。
AI 最大的价值之一：让我们可以在合适的阶段暂时放下大量实现细节，把有限的注意力集中到真正高价值的事项上——问题定义、方案权衡、边界与验收。
  • 人更应聚焦：要解决什么问题、怎样算完成、优先级与约束
  • AI 适合承接：具体实现、样板代码、重复性修改、扩写与重构
  • 充分思考与规划是 ROI 最高的投入；懒人模式则既少想、也少验，把决策和验收一并外包，效果最差
  • 认真检查 vs 几乎不检查，产出质量往往是「天上地下」的差别——这也是懒人用不好 AI 的重要原因

注：实现细节并非不重要，而是分工——细节仍要审查与验收，但不必全部由人从零手工完成。

Part 03

策略层

策略层

贵模型想明白，普通模型干明白

场景建议模型档位
架构规划、方案权衡、疑难排障高能力模型
批量修改、模板代码、重复劳动普通模型
原则：质量与成本主动分层，避免全程顶配
策略层

Cursor / Codex：从写代码到做「严肃脑力活」

  • 适用：复杂调研、规划、方案设计
  • 优势：文档化缓解上下文限制
  • 对比网页版：投喂资料与沉淀产出都更可持续
策略层

Rules / Skills：用起来，才真正懂

  • 能固化约定、显著提升效率与质量
  • 前提是你先理解它们解决什么问题、该约束什么
  • 有意识地多用、多改、多复盘；只抄模板，效果往往有限
  • 同类新工具还会涌现：选择性采用、刻意练习，不盲目跟风
Part 04

方法层

方法层

复杂项目：试试「Sprint 节奏」

  • 每个 Sprint：规划 → 执行 → 验收 → 总结
  • 可能更慢，但清晰度、可控性显著提升
  • 适合：需求多变、周期长、多轮 AI/多人接手的项目
方法层

让代码和测试成为「活文档」

  • 实例化需求：用具体用例描述行为，减少歧义
  • TDD：先定义可验证行为，再驱动实现
  • AI 也会偷懒：稍不留意，输出质量就会打折——表面能跑、边界遗漏、改动不完整等
  • 人工把关：自动化测试之外，认真检查同样不可或缺；认真验 vs 几乎不验，质量往往天上地下
  • 经测试与验收验证的规范，可沉淀为 Rules / Skills
结果：测试 + 人工验收双保险，质量 ↑、可维护性 ↑、人机交接成本 ↓
方法层

做好版本管理——Git 值得人人学

  • 强烈建议学 Git：代码与文档（.md、方案、配置）都应纳入版本管理，会提交、看历史、回滚
  • AI Agent 也会出 bug：误删、改错、覆盖难以完全避免——Git 是回滚与找回的底线
  • 作者曾两次惨痛丢失代码与文档；不懂传统开发也应先建立 commit 习惯
  • CI/CD、部署、环境同样琐碎；及时 commit，并让 AI 帮你沉淀 Runbook
Part 05

沉淀层

沉淀层

每一次踩坑，都该变成下一项目的垫脚石

  • 项目内：需求说明、架构决策、部署 Runbook、复盘
  • 项目间：可复用的检查清单与模板
  • 对新 AI / 新同事：文档即上下文，降低重复解释成本
沉淀层

习惯 Markdown 与 Mermaid，降低协作摩擦

  • Markdown：结构清晰、版本友好，适合需求、方案、复盘、Runbook
  • Mermaid：与 MD 同源、可内嵌，用流程图、时序图、架构图表达协作流程与系统边界
  • 图示往往比长段文字更少歧义，且同样便于 AI 阅读与修改
  • 推荐：MarkText；Mermaid 可在 GitHub / Cursor 等环境直接渲染
Markdown 写清楚文字，Mermaid 画清楚结构——二者都是人与 AI 协作的极佳媒介
结　语

三条带走就能用的原则

1

人先想清楚、人下指令，再让 AI 动手——你告诉 AI 做什么，细节交给 AI，注意力留给高价值决策

2

复杂项目：Sprint 节奏 + 实例化需求 + TDD

3

一切经验文档化，用 Markdown 与 Mermaid 连接人与 AI

AI 不会替代思考；它放大的是——你已经想明白的那部分。
